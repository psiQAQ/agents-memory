# 企业记忆管理方案:负责人思想

本文件记录负责人对方案的基本设想,优先级较高。要改动这里的基本思想,先和负责人确认。
本文件为搭建框架的最初头脑风暴，通过类似数学公理假设出发，从 agent 常见的基础功能（MCP/Skills/hooks/subagents/...）出发逐步列出约束和需求，以人的信息处理能力限制来参与 agent 的框架搭建工作。

> 整理说明(2026-08-07):对基本思想做了分类;删去原「五个方向」展开章节;新增「参考实现」章节(从 submodules 抽取)。思想本身没有改动。

## 方案基本思想

一句话:谁能看到什么、看到多细,由身份和项目披露关系决定;价值由 AI 先判、由查询人定颗粒度;全部通过 MCP 按身份调取。

### 谁能看、看多细

- 身份决定可见范围和颗粒度,不同身份看到的内容不同。
- 项目有上下游依赖,记忆按披露程度跨项目流动。
- 记忆价值 AI 先给初判,最终由查询人决定要看到哪一层。

### 记忆怎么产生、放哪

- 颗粒度用提示词或身份模板约束;本地 agent 按身份生成和更新披露文档。
- 知识库以子模块形式挂在项目仓库里,本地 agent 维护,远端 MCP server 统一同步。

### 怎么调用、别被绑死

- 记忆用 MCP 管理,身份登录加项目认证,支持跨级调取。
- 架构需要兼容不同款 agent（claude code/codex/...）。
- 当 agent 不可用时,也有人工手动维护的备选方案。

## 参考实现:搭建思想与技术栈

从公开 Agent 记忆项目的调研中提炼可参考做法，为上述思想寻找现成参照。逐个项目的详细分析在 [项目参考](../references/projects/) 下。

### 搭建思想(别人是怎么想的)

- Mem0:大部分对话不该记;要记就一次 LLM 提取成一条条原子事实,只加不改、留全历史。
- Graphiti:事实带时间戳,变了就把旧的标失效、不删,能回查"那会儿什么是真的"。
- Letta:记忆是 agent 自己能调工具改的"块";正本放 Git,数据库只当缓存。
- LangMem:记忆分三种——事实、经历、习惯;写入分两条道,一条当场写,一条等安静时再整理。
- claude-mem:用 hook 无感地抓,后台压成结构化的 observation;抓取出错就静默退出,绝不打断人干活。
- basic-memory:Markdown 加 Git 才是正本,索引只是投影,删了随时能重建。
- TencentDB Agent Memory:面向团队;记忆分 L0-L3 四层,拆成对话/技能/wiki/代码图四类资产;隔离和过滤在存储层就卡死。
- MemRL:用任务成没成来给记忆打分,好用的升值、没用的沉底;必要时"不给"也是一种选择。

### 技术栈(别人拿什么搭的)

- 语言:多数是 Python(mem0/graphiti/letta/langmem/basic-memory/MemRL);贴 Claude Code、编辑器那两个用 TypeScript(claude-mem、TencentDB Agent Memory)。
- 存:向量库几乎人手一个,但选型很散——本地单机爱用 SQLite+Chroma、faiss;多人服务化爱用 Qdrant、pgvector、腾讯云向量库。pgvector 出现最多(关系库顺带管向量,省事)。
- 图库是可选加强,不是必需——只有 Graphiti(当核心)、Mem0/Letta(可选)用 Neo4j/FalkorDB 那类,留给时序和多跳关系。
- 查:普遍是"语义(向量)+ 关键词(BM25),有时再加图遍历",几路合起来重排。
- 接:8 个里 6 个自带 MCP server(只有当 SDK 的 LangMem 和做研究的 MemRL 没有)——说明"拿 MCP 当统一调用口"这条路走得通。
- 提取和结构化:基本都靠 schema 卡类型(Python 用 pydantic、TS 用 zod),配 openai/anthropic/litellm 这类 LLM 接口。

### 对本方案的印证

- 想法都能落地:submodule 挂知识库、Markdown+Git 当正本、MCP 统一调用、失效不删、写入分道——每条基本思想都能在某个开源项目里找到现成做法。
- 但没有一个能直接拿来用:团队级的角色分级披露、检索前按身份过滤、候选到审核到生效的治理,这几样开源项目都缺,得自己补。
