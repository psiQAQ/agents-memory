# Attestation 信任边界补充决策

> **Attestation**：宿主预检后交给容器复核的短期 JSON 记录；本项目没有为它添加数字签名或消息认证码。

- 日期：2026-08-09
- 状态：Accepted
- 适用范围：付费模型 Gate 与 Windows 项目配置 Gate

## 背景

现有 Gate 会核对宿主绝对真实路径、批准参数、实际挂载和十五分钟时效。早期决策与静态复验报告把该行为概括成“篡改被拒绝”，但这句话没有写出本地信任前提，容易被理解为具备加密防伪能力。

## 决策

Attestation 只用于防止意外误配置、字段不一致和过期记录复用。宿主账户、Compose 启动环境与实验证据目录属于受信任边界；能同时改写 attestation 和环境变量的本地操作者不在该控制的威胁模型内。

本阶段不增加签名、消息认证码、外部审批服务或硬件密钥。若未来需要抵抗恶意本地操作者，必须重新设计密钥托管、审批签名和验证方，而不能把当前 JSON 记录视为安全证明。

## 影响

- 当前实现和 45 项静态测试结果不变。
- `docs/decisions/2026-08-09-host-path-and-no-follow-hardening.md` 与 `docs/reproduction/2026-08-09-docker-compose-security-gates-static.md` 保留为不可变历史记录；其中“篡改被拒绝”应按本决策限定为“在受信任宿主边界内，字段不一致或过期记录被拒绝”。
- 管理者文档和操作说明必须显式展示此信任边界。
